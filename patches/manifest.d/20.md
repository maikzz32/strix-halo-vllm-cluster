## 20_rocm_smi_rtld.py

- **Purpose:** Make the rtld mode of torch's ROCm library preload in
  `torch/_rocm_init.py` runtime-switchable. torch 2.13+rocm7.14 (TheRock
  wheels) loads librocm_smi64 & friends via
  `rocm_sdk.initialize_process(preload_shortnames=[...])` whose
  `rtld_global` parameter defaults to True (`RTLD_GLOBAL`) — already the
  mode our builds needed. Target file belongs to the installed torch
  wheel, not the vLLM checkout (located via
  `importlib.util.find_spec("torch")`). With the TheRock loader the mode
  applies to ALL preloaded libraries, not just rocm_smi64 — the
  per-library CDLL call no longer exists; the knob's blast radius is the
  whole preload set (that IS the A/B experiment).
- **Unresolved conflict (documented, not decided):** two mutually
  exclusive fixes exist for the clash —
  - this repo's original patch forced `RTLD_GLOBAL` (re-opening the
    library globally resolved the clash on our builds);
  - LucRoot's gfx1151 build record claims the clash is fixed by the
    opposite, `rtld_global=False` (i.e. `RTLD_LOCAL`).
  Both cannot hold at once, and neither can be confirmed without
  hardware. The patch therefore rewrites the CDLL call to resolve the
  mode LAZILY at torch import time instead of hardcoding it.
- **Env knob:** `VLLM_GFX1X_ROCM_SMI_RTLD` = `global`|`local`, read with
  `os.environ.get(..., "global")` at import time — **default stays
  `global`**. Both emitted branches carry the
  `# gfx1151-patch: 20_rocm_smi_rtld` marker, so `--check` passes
  regardless of the active mode.
- **Default must be decided empirically:** at the first hardware run,
  A/B `VLLM_GFX1X_ROCM_SMI_RTLD=global` vs. `=local` (symbol-clash
  traceback at torch import vs. clean start, plus a smoke inference);
  record the outcome in docs/RUNBOOK.md and pin the winner as the new
  default (or drop the switch if upstream torch settles it).
- **Status:** re-audited against torch 2.13.0+rocm7.14.0 (TheRock
  loader; patch verified against the real wheel file: apply / --check /
  idempotence / `ast.parse` all pass). Pre-TheRock wheels (per-library
  `ctypes.CDLL(rocm_smi...)`) are detected and rejected with exit 42.
- **Re-audit trigger:** exit 42 (no unique `rocm_sdk.initialize_process(`
  call, no unique `def initialize():`, call not alone on its line,
  pre-TheRock CDLL layout detected, or the patched file fails
  `ast.parse`).
- **Validate on hardware:** torch import with both modes; watch for the
  rocm_smi symbol-clash error, `amd-smi`/`rocm-smi` functionality after
  import, and any interference with patch 59's fast path (which skips
  the amdsmi probe at vLLM level, not at torch level).
- **Date:** 2026-09-01.
