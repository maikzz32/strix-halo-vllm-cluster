# 51_radix_topk.py

- **Purpose:** Route the sparse indexer's `top_k_per_row_prefill` /
  `top_k_per_row_decode` calls through a deterministic Triton radix-select
  top-k (`select_topk` in the vendored `gfx1x_radix_topk.py`) on gfx1x.
  Radix selection over integer histograms replaces the two-sort torch path;
  output is ascending by column index, `-1`-padded, and bit-identical run to
  run (no atomics, no FP accumulation, no shape-dependent JIT key).
  **Measured claim (source hardware: Strix Halo gfx1151): 2.2-8.6x** on the
  top-k stage.
- **Targets:**
  - copies `patches/vendor/gfx1x_radix_topk.py` to
    `vllm/v1/attention/ops/gfx1x_radix_topk.py`;
  - rewrites `vllm/v1/attention/ops/rocm_aiter_mla_sparse.py`: injects a lazy
    dispatcher before `rocm_aiter_sparse_attn_indexer_fake` and guards the
    two `torch.ops._C.top_k_per_row_*` call sites with
    `_gfx1x_radix_topk(...)`, upstream call retained as fallback. (vLLM
    v0.28 removed the AITER top-k if/else dispatch in this file; the call
    sites are unconditional now — anchors re-audited against v0.28.0.)
- **Env knobs:** `VLLM_GFX1X_RADIX_TOPK` (default `1` = ON — the target file
  only serves DeepSeek-style sparse indexers; set `0` to keep upstream),
  `VLLM_GFX1X_TOPK_HIST` (`hist` default / `sum` fallback that avoids
  `tl.histogram`; both modes must emit identical output — validation step).
  Both resolve lazily (Ray applies worker env after import).
- **Upstream references / provenance:**
  - vendored kernel:
    <https://github.com/kyuz0/amd-strix-halo-vllm-toolboxes>
    `scripts/gfx1x_radix_topk.py` @
    `614c91789e4609601e618a8d967390c04896acab`, itself adapted from
    AlexKGwyn/ds4-vllm-public @ `95c45bb94f324fcf3f58ec1f5eaf2d1aaceb87ff`;
    Apache-2.0.
  - dispatch logic ported from the same repo's `scripts/patch_dsv4_gfx1x.py`
    (`patch_sparse_indexer_topk`), adapted to current upstream: older vLLM
    wrapped the `torch.ops._C.top_k_per_row_*` calls in an AITER top-k
    dispatch and the radix path hooked the non-AITER `else:` branches;
    vLLM v0.28 (re-audited @ v0.28.0) dropped that dispatch, so the patch
    wraps the now-unconditional call sites directly. If a future build
    re-enables an AITER top-k kernel on gfx1x, the dispatch has to be
    re-audited against this patch.
- **Per-model validation gate:** kernel semantics (top-k over `[ks, ke)` of
  the indexer logits) are DeepSeek-style-generic. Qwen3.8 QSA and GLM-5.3
  sparse-MLA indexers differ in head count / index dim / page layout and
  **must be validated per model before enabling** (compare against
  `VLLM_GFX1X_RADIX_TOPK=0` output). Validation steps: (1) hist vs sum mode
  produce identical indices; (2) radix vs upstream torch fallback produce
  identical top-k sets on captured logits; (3) end-to-end logit parity per
  model.
