## 56_apu_memory_reporting.py

- **Purpose:** Prerequisite fix for correct KV-cache budgeting on Strix
  Halo. HIP memory APIs report only the ~15.5 GiB VRAM aperture as total
  memory instead of the ~110+ GiB GTT/unified region (ROCm/hip#3892), so
  `--gpu-memory-utilization` and KV profiling budget against a wrong total.
  Ports the vllm#40963 approach (detect AMD APU, read sysfs
  `mem_info_gtt_total`/`mem_info_gtt_used`, reserve 8 GiB for system/driver
  overhead).
- **Targets:**
  - `vllm/platforms/rocm.py`: adds `RocmPlatform.is_integrated_gpu()`
    (detection: gfx1150/gfx1151/gfx1152 arch, PCI device ID `0x1586`, or the
    vllm#40963 sysfs-vs-HIP >4x heuristic), `apu_gtt_total_memory()`, and a
    `mem_get_info()` classmethod mirroring vllm#40963; short-circuits
    `get_device_total_memory()` to the sysfs GTT total on APUs.
  - `vllm/utils/mem_utils.py`: `MemorySnapshot.measure()` additionally
    corrects `total_memory` on ROCm APUs — the existing UMA fix there only
    repairs `free_memory` (via psutil) once `is_integrated_gpu()` is true,
    but the KV budget (`init_snapshot.total_memory *
    gpu_memory_utilization`) needs the corrected total too.
- **Env knob:** `VLLM_GFX1X_APU_MEM_REPORT=0` kills the whole fix
  (lazy resolution — Ray applies worker env after import).
- **Companion:** expandable segments stay important on UMA; registry
  defaults already set `PYTORCH_HIP_ALLOC_CONF=expandable_segments:True`
  (ROCm's name for `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`).
- **Upstream references:** vllm#40963, ROCm/hip#3892. Anchors verified
  against vLLM dev tag v0.28.1rc0 (79651d6085885cf2842baf85526ece7afa87c87d).
- **Status:** expected-to-need-adjustment. If vllm#40963 (or a successor)
  lands upstream, anchors move and this patch exits 42 — then most of it is
  likely obsolete; re-audit instead of force-applying.
- **Re-audit trigger:** exit 42 (`is_navi`/`get_device_total_memory`/
  `MemorySnapshot.measure` anchors gone).
- **Validate on hardware:** `rocminfo`/sysfs GTT total vs. the total vLLM
  logs at startup (~110+ GiB, not ~15.5 GiB), KV cache size at
  `--gpu-memory-utilization 0.9`, and no regression on dGPU ROCm hosts
  (detection must stay False there).
- **Date:** 2026-08-30.
