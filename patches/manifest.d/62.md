# 62_glm53_mtp_draft_bf16.py

- **Purpose:** Unblock MTP speculative decoding (`--speculative-config
  '{"method":"mtp",...}'`) for GLM-5.3-Flash with the local int4 re-quant
  (`/home/maik/glm53_flash`). The MTP draft (`Glm5NextMTP`) loads from the
  same checkpoint and inherits the target's compressed-tensors int4 method
  via `SpeculativeConfig.__post_init__` — but the checkpoint keeps the
  whole MTP layer (45) in BF16 (2334 llm-compressor ignore entries, zero
  `weight_packed` keys under `layers.45.`; checkpoint ignore names
  `model.language_model.layers.45.*` can never match draft module prefixes
  `model.layers.45.mtp_block.*`, probed `should_ignore_layer` = False).
  Without the patch the draft load dies on the first BF16 expert weight
  handed to a WNA16-packed param. The patch forces the whole MTP layer
  quant-free in `Glm5NextMultiTokenPredictorLayer.__init__`
  (`vllm/models/glm5next/nvidia/mtp.py`): `quant_config = None` for
  `SharedHead` (its LM head is always replaced by the target's BF16 lm_head
  in `llm_base_proposer`) plus `copy.copy(vllm_config)` with
  `quant_config = None` for `Glm5NextDecoderLayer` (-> MoE routed experts
  AND the `n_shared_experts=1` shared-expert MLP, both BF16 in the
  checkpoint). MLA projections / indexer are already hard-coded BF16 in
  `Glm5NextDecoderLayer`.
- **Runtime-first provenance:** none yet — spec'd in the MTP enablement
  research (2026-09-01) as the one blocking code gate for MTP on gfx1151
  after patches 58/61 + kpool torch lane v1.4. NOT applied to the running
  containers; validated against a /tmp copy of the installed mtp.py
  (apply / re-run idempotence / --check / ast.parse / diff hunk). First
  real proof is the first `vllm serve` with the `glm53-flash-mtp` registry
  entry (coordinator rollout).
- **Target:** `vllm/models/glm5next/nvidia/mtp.py`. Anchors (verbatim,
  exactly 1 match each): the `import typing` / `from collections.abc`
  import pair (-> add `import copy`), and the 4-line `assert
  vllm_config.speculative_config is not None` ... `quant_config =
  vllm_config.quant_config` block at the top of
  `Glm5NextMultiTokenPredictorLayer.__init__`.
- **SKIP semantics:** no glm5next package (stable/main builds without PR
  #53906) -> SKIP 0. glm5next present but an anchor moved -> exit 42.
  `ast.parse` before write. Marker-idempotent.
- **Re-audit trigger:** exit 42, or the post-apply WARN about surviving

- **Warning:** checkpoint-specific, like patch 61 — do NOT apply when
