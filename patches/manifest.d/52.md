# 52_tilelang_sparse_indexer.py

- **Purpose:** Route the paged (decode) and non-paged (prefill) FP8 MQA
  logits paths of the DeepSeek-style sparse indexer through vendored TileLang
  kernels on gfx1x. The TileLang GEMM runs in BF16 because gfx1151 has no
  native FP8 matrix-core dot (FP8 remains the storage format); the paged path
  de-shuffles vLLM's ROCm 16x16 paged-cache layout back to token-major rows
  first. **Measured claim (source hardware: Strix Halo gfx1151): ~47x** on
  the indexer kernel vs the torch fallback.
- **Targets:**
  - copies `patches/vendor/gfx1x_tilelang_mqa.py` to
    `vllm/v1/attention/ops/gfx1x_tilelang_mqa.py`;
  - rewrites `vllm/v1/attention/ops/rocm_aiter_mla_sparse.py`: injects a lazy
    dispatcher (`_gfx1x_tl_mqa_impl`) before `rocm_fp8_paged_mqa_logits` and
    inserts gfx1x dispatch branches ahead of the
    `aiter_paged_mqa_logits_module = None` / `aiter_mqa_logits_module = None`
    fallbacks. Upstream AITER/torch paths are retained whenever the gate is
    off, the arch is not gfx1x, or `tilelang` fails to import (warning
    printed once, then sticky fallback).
- **Env knobs:** `VLLM_GFX1X_TL_DECODE` (paged path), `VLLM_GFX1X_TL_PREFILL`
  (non-paged path); both default `1` = ON (the target file only serves
  DeepSeek-style sparse indexers; set `0` to keep upstream). Resolved lazily
  (Ray applies worker env after import).
- **Hard requirements** (restated in the vendored module; do not relax when
  rebasing):
  - decode kernel threads MUST be 256 — 128 produces wrong logits;
  - `block_N >= 256` overflows the 64KB LDS budget on gfx1151
    (`_fit_prefill_config` caps shared memory at 56KB);
  - KV-length bucketing (512 decode / 8192 prefill) is what prevents
    mid-decode JIT stalls — measured 16 -> 1.5 tok/s without it.
- **Upstream references / provenance:**
  - vendored kernels:
    <https://github.com/kyuz0/amd-strix-halo-vllm-toolboxes>
    `scripts/gfx1x_tilelang_mqa.py` @
    `4802c7be1fbadec96a54525526ea5111276a1480`, adapted from
    AlexKGwyn/ds4-vllm-public `ds4_tl_indexer.py` (the ds4 -> kyuz0
    adaptation adds the ROCm 16x16 paged-cache de-shuffle); Apache-2.0.
  - dispatch logic ported from the same repo's `scripts/patch_dsv4_gfx1x.py`
    (`patch_sparse_indexer_mqa`), with the per-path env gates added; anchors
    verified against vLLM main @ `56058fd572f6a7fec6899385f4a4ed7f4b964477`.
  - requires the `tilelang` Python package in the image (build dependency,
    owned by the Dockerfile scope).
- **Per-model validation gate:** kernel semantics
  (`sum_h relu(q.k) * w * scale`, logits over `[ks, ke)`) are
  DeepSeek-style-generic. Qwen3.8 QSA and GLM-5.3 sparse-MLA indexers differ
  in head count / index dim / page layout and **must be validated per model
  before enabling** (compare against `VLLM_GFX1X_TL_*=0`). Validation steps:
  (1) TileLang logits vs upstream torch logits allclose on captured inputs,
  per model; (2) cache geometry check — block size and index head dim must be
  divisible by 16 (`_logical_cache_values` raises otherwise); (3) watch for
  JIT stalls on first decode at a new KV bucket.
