## 53_w8a8_bf16_skinny.py

- **Purpose:** Cached-BF16 W8A8 skinny-GEMM decode path for gfx1151 (RDNA 3.5
  has no native FP8 matrix cores). Two mechanisms, ported from
  kyuz0/amd-strix-halo-vllm-toolboxes (`patch_dsv4_gfx1x.py`) and
  AlexKGwyn/ds4-vllm-public:
  1. `vllm/model_executor/layers/quantization/utils/fp8_utils.py`: adds a
     `USE_BF16_DOT` constexpr to the Triton block-scaled FP8 GEMM kernel; on
     gfx1x the operands are cast to BF16 before `tl.dot` (RDNA 3.5 WMMA
     supports BF16 natively via Triton).
  2. `vllm/model_executor/kernels/linear/scaled_mm/triton.py`: overrides
     `apply_weights` on `TritonFp8BlockScaledMMKernel` so small-M decode runs
     against a cached dequantized BF16 weight copy through vLLM's ROCm
     unquantized dispatcher (hipblaslt `wvSplitK` skinny GEMM at M<=5, ~24x
     vs. the untuned Triton block-scaled GEMM at M=1). Also hooks
     `_w8a8_triton_block_scaled_mm_func` for the already-quantized fallback.
     Installs the vendored helper `patches/vendor/gfx1x_w8a8_bf16.py` into
     the same package (keeps `_MAX_COLD_CACHE_ROWS=32`: the BF16 cache is
     only populated by small-M decode calls, so startup KV profiling still
     measures the stock FP8 path).
- **Env knobs (lazy; Ray applies worker env after import):**
  `VLLM_GFX1X_W8A8_BF16=1` (master), `VLLM_GFX1X_W8A8_BF16_DIRECT=1` (skip
  the activation FP8 round trip), `VLLM_GFX1X_W8A8_BF16_PREFILL=0` (disable
  BF16 cache for large-M prefill; consumed by the vendored helper),
  `VLLM_GFX1X_W8A8_BF16_MIN_TP=N` (default 2 — the BF16 weight duplicate
  costs memory; kyuz0 enables this only for TP2 profiles because TP1
  exceeds memory headroom). Unknown/uninitialized TP fails safe (path off).
- **Targets:** the two files above plus the installed vendor module; all
  located defensively (relative path, then name search).
- **Upstream references:** kyuz0/amd-strix-halo-vllm-toolboxes
  (`scripts/patch_dsv4_gfx1x.py`, `scripts/gfx1x_w8a8_bf16.py`),
  AlexKGwyn/ds4-vllm-public. Anchors verified against vLLM dev tag
  v0.28.1rc0 (79651d6085885cf2842baf85526ece7afa87c87d).
- **Status:** expected-to-need-adjustment. Layout difference vs. kyuz0's PR
  base already handled: at the dev tag the block-scaled FP8 kernel is
  `TritonFp8BlockScaledMMKernel` and the inherited `apply_weights` lives in
  `Fp8BlockScaledMMLinearKernel` (the override's `super()` target).
- **Re-audit trigger:** exit 42 (any of the 7 anchors gone, e.g. upstream
  adopting a BF16 dot or restructuring `scaled_mm/`). Also re-audit if
  `rocm_unquantized_gemm_impl` disappears from
  `vllm/model_executor/layers/utils.py` (imported lazily by the vendor
  module; present at v0.28.1rc0).
- **Validate on hardware:** BF16-direct diagnostic line in the logs,
  decode tok/s at M=1 vs. unpatched (expect order-of-magnitude gain on
  FP8 block-scaled models), and memory headroom at TP1 (path must stay off).
