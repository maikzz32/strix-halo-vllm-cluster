# 73_qsa_draft_decode_metadata_update.py

- **Purpose:** Let the k-step MTP draft run as ONE fused loop (and therefore
  fit into one full CUDA graph) instead of rebuilding attention metadata in
  Python between every draft step. vLLM's autoregressive speculator picks
  `_fused_multi_step_decode` only when every attention backend advertises
  `supports_draft_decode_metadata_update`
  (`_configure_fused_multi_step_decode`,
  `vllm/v1/worker/gpu/spec_decode/autoregressive/speculator.py:100-125`).
  Ours does not, so the cluster logs `Fused multi-step draft decode is not
  supported by attention backend(s) QWEN4_EXP_EXP_QSA_STATE; falling back to
  rebuilding attention metadata between draft steps` and takes
  `_multi_step_decode`, which per step runs `compute_slot_mappings` +
  `build_slot_mappings_by_layer` + a full `_build_draft_attn_metadata`
  (a CPU `torch.zeros`, CPU arithmetic, and a Python metadata object rebuild)
  outside any graph. The patch sets the flag on `QSAMetadataBuilder` and
  implements the method as a relaunch of the same `build_qsa_metadata`
  Triton kernel over the same persistent buffers.
- **Why this is legal for QSA (read out of the source, not assumed):**
  `step` changes exactly ONE value in `_build_draft_attn_metadata`
  (`vllm/v1/worker/gpu/spec_decode/speculator.py:251`) — the CPU-side
  `draft_seq_lens_cpu_upper_bound` — and the QSA builder never reads
  `seq_lens_cpu_upper_bound` (grep: zero hits in `qsa_cache.py`). Its
  step-dependent inputs (`seq_lens`, `slot_mapping`, `query_start_loc`) are
  persistent GPU buffers owned by the speculator and refreshed before the
  call; its outputs are the builder's own `token_to_req_buffer`,
  `logical_positions_buffer`, `slot_mapping_buffer` and
  `k_work_metadata_buffer` from `__init__`; every Python-side scalar
  (`num_tokens`, `num_reqs`, `request_scan_size`, `max_num_work`) is
  step-independent for a uniform draft-decode batch. Precedent:
  `vllm/v1/attention/backends/mla/sparse_swa.py:658` relaunches its own
  Triton kernel the same way. The Triton backend's implementation
  (`triton_attn.py:270`) is empty only because nothing there is derived —
  the flag is a promise that step-dependent fields point at persistent
  buffers, not a promise of a no-op.
- **Measured motivation:** 2026-09-06, TP4, `qwen38_rest`, ShareGPT c=1:
  iteration time fits `31.8 ms + 7.25 ms x k` to within 0.2 ms
  (k=0 31.8 / k=3 53.7 / k=4 60.8). One draft step — a SINGLE layer — costs
  11x what a target-model layer costs. 60 tok/s needs 3.88 ms per step.
- **Runtime-first provenance:** NONE yet. Written from the installed source
  in the `ray-head` container, syntax-validated locally (all three
  replacements applied to a skeleton -> `ast.parse` clean), but not yet
  applied to any node and not yet benchmarked. First proof will be a TP4 run
  whose log no longer contains the "Fused multi-step draft decode is not
  supported" line, at unchanged accepted-tokens-per-iteration.
- **Target:** `vllm/models/qwen4_exp/common/qsa_cache.py`. Three anchors
  (verbatim, exactly 1 match each, enforced before any write): the
  `class QSAMetadataBuilder` header through its `_cudagraph_support` line;
  the `token_to_req, logical_positions, slot_mapping = build_qsa_metadata(`
  call in `build()`; and the tail of the `return QSAForwardMetadata(...)`
  block immediately before `class QSAStateBackend(AttentionBackend):`.
- **SKIP semantics:** no `vllm/models/qwen4_exp` package -> the file is
  absent -> exit 42 with "not found" (registered in `verify_compat.py`
  under `CONDITIONAL`, so a tree without the model package SKIPs the marker
  check). Anchor moved -> exit 42. Marker-idempotent (re-run prints SKIP).
- **Gate:** `VLLM_GFX1X_QSA_FUSED_DRAFT=1` (default) / `0` reverts to the
  per-step rebuild WITHOUT reinstalling, so it is a safe A/B switch. The gate
  sits on the CLASS ATTRIBUTE (evaluated at import), not inside the update
  method, because that attribute is what the speculator reads once at startup
  to choose a path. An earlier draft of this patch gated the method body
  instead — that would have left the fused path selected while silently
  skipping the refresh, i.e. drafting on stale metadata. Import-time
  evaluation is correct here: the environment is fixed for the worker's life.
- **Re-audit trigger:** exit 42; upstream giving `QSAMetadataBuilder.build()`
  a step-dependent Python scalar; or `_build_draft_attn_metadata` starting to
  vary more than `seq_lens_cpu_upper_bound` with `step`.
- **Depends on:** patch 65 (`VLLM_GFX1X_SPEC_CUDAGRAPH`) — the full benefit
  needs the fused path AND `=1`, so that all k steps land in one graph.
- **Date:** 2026-09-06.
