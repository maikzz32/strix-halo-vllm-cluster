# AITER gfx1151 tiles against the existing HC kernels

The concrete small-M configuration from [AITER PR4814](https://github.com/ROCm/aiter/pull/4814)
does not improve this model's HC projections. The isolated Node18 test uses the
same BF16 inputs and weights for both methods, FP32 accumulation in the AITER
kernel, and no activation or weight quantization. No model source or installed
package was changed.

| Target shape, M=4 | Existing kernel | AITER tile | Latency change |
|---|---:|---:|---:|
| Merged down, N336/K10240 | 42.45 µs | 56.18 µs | +32.3% |
| Final down, N320/K10240 | 49.03 µs | 54.85 µs | +11.9% |
| Up, N10240/K320 | 34.33 µs | 35.86 µs | +4.5% |

Each shape uses 24 different matrices, a 150–157.5 MiB weight pool, captured
graphs, five samples and 20 replays per sample. Times exclude compilation and
allocation. Actual cache miss rates are not measured. The baseline is the
installed `rocm_unquantized_gemm_impl`, not ordinary `torch.addmm` used in the
public comparison. Peak tensor memory stayed below 250 MiB.

AITER was not installed in the preserved container. The test therefore extracts
the reviewed Triton kernel and its two PID helpers from PR head
`df9d0a8a6fd2151eaf8bf5f74e8cd0c983fb8320`. Its arithmetic body and heuristic
specializations are unchanged. The AITER debug-name factory, package imports and
general dispatcher are omitted. A small adapter reproduces the bias-free,
SplitK=1 launch for the three exact shapes. This measures the isolated kernel
and tile, not an installed AITER integration. The existing Triton 3.8 compiler
and Torch 2.13/ROCm10 are used. See the [source review](aiter4814-hc-sourcecheck-20260907.md).

The tile is BM32/BN16/BK256, two warps, two stages and one wave/EU. The original
`stride_ck=0` argument and corresponding upstream assumption were preserved;
the tested compiled kernels produced finite results and correct graph replays.
This observation does not resolve that source inconsistency for other compilers.

Every matrix is checked against FP32 and the original kernel. BF16 output bits
are not all identical to the baseline: the reduction order differs. Graph
outputs are bit-identical to separate eager executions with changed inputs and
to their original outputs after restoring the inputs. These are synthetic
operator checks, not a model-quality evaluation.

The first test stopped at an overly strict assertion that the result after
negating the input must equal the negation of the previous floating-point
result. The corrected test uses actual eager execution as its replay oracle.
The Up case differs from algebraic negation at only two output values across
24 matrices, maximum absolute difference 0.00048828125; eager and graph agree
exactly. Zero-sign differences in the padded Down rows are also recorded.
The first partial result is retained alongside the complete second run.

Both child processes exited and the corrected environment-marker scan confirmed
no owned process remained. The model's completed-request counter stayed at 54
throughout the tests. The canonical QSA/RCCL service stayed running.
