# Isolated native HC kernels on gfx1151

The lossless format does not improve the common HC operators overall and was not deployed. TP4/UMA serving remained unchanged throughout all seven experiments.

The final test uses 24 synthetic BF16 matrices per shape (at least 150 MiB), five samples of 20 captured-graph replays, and the installed vLLM operator as the timing and numerical control. HIP reports `multi_processor_count=20`, which is passed unchanged to both isolated kernels. These are operator timings, not serving throughput measurements.

| M,N,K | Installed (us) | Packed U2 (us) | Original U1 (us) | Original U2 (us) |
|---|---:|---:|---:|---:|
| 4,336,10240 merged down | 43.351 | 62.082 | 51.343 | 43.056 |
| 4,320,10240 final down | 49.555 | 39.024 | 46.671 | 47.352 |
| 4,10240,320 up | 34.672 | 45.393 | 35.384 | 31.897 |

Packing saves approximately 23.9% for these synthetic matrices, including descriptors. It wins only for the rare final down projection. The uncompressed U2 up kernel lowers operator time by 8.0%; about 96 such calls would save only 0.27 ms per target round if the gain carries through. That is an estimate below 1% of the earlier full-model time budget, not a measured model improvement.

Every packed matrix was unpacked on GPU and compared bit for bit with its original. All tested GEMM variants matched the installed operator on all 72 matrices, including graph replay after changing inputs. This does not establish parity for all actual model tensors or every possible BF16 input. The earlier actual-weight CPU survey remains separate evidence. Original tensors remain allocated for comparison, so this benchmark does not measure serving memory savings.

Seven variants cover separate sign/mantissa and exponent planes, pairwise integer decoding, an eight-wave override, contiguous 12-bit encoding, packed unroll factors 1/2/4 and original unroll factors 1/2. All samples and cleanup/service checks are in the [record](../bench/records/2026-09-07-hc-native.json). No owned experiment process remained; serving request counters stayed unchanged. Assembly from the U1 packed build reports zero private scratch for the inspected kernels; scratch spilling is not an established cause of the slowdown.

The final format packs two 12-bit codes into three bytes. Each 256-value block has a four-byte descriptor with exponent base, raw fallback flag and aligned payload offset. Blocks whose exponent span exceeds 15 retain their original BF16 bytes. Integer decoding reconstructs BF16 operands before the original arithmetic.

## Reproduction

Download the pinned [vLLM source](https://github.com/vllm-project/vllm/blob/33898f832/csrc/rocm/skinny_gemms.cu) as raw bytes. The generator requires SHA256 `013f14b570cd8f25e254bf47643ba2802ab7d5fdd2069adb111bc6ff560f6682`; preserve LF line endings. Apache licensing is retained in `tests/third_party/VLLM-LICENSE`.

`tools/run_hc_lossless_build.py --source PATH --output NEW_DIRECTORY` previews an isolated Node18 build; `--execute` compiles it in the existing container. Use its reported library path and binary SHA with `tools/run_hc_lossless_experiment.py --library PATH --library-sha256 SHA --output NEW_DIRECTORY`; add `--execute` to run. Both drivers default to dry run. The benchmark is specialized for the three documented M4 shapes and the existing patched runtime; it is not a production adapter. Generated native sources and raw logs are retained in the local workspace results directories.
