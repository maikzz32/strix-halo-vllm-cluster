# HC launch geometry and unrolling — isolated results

Strix Halo has 40 physical RDNA 3.5 compute units. The tested PyTorch/HIP
runtime reports `multi_processor_count=20`; this API value must not be
presented as the physical CU count. Here the native operator's `cu` argument
controls launch geometry and row assignment. Changing it does not change
the hardware or the stored BF16 weights.

Two isolated node 4 tests use 24 distinct synthetic matrices per shape,
six alternating timing rounds and 20 graph replays per round. Every candidate
must match the installed operator bitwise in eager execution and in a graph
after changing inputs. All checks passed for the completed runs.

| M4 operator | Installed, seed 9501 (us) | Selected grid, seed 9501 (us) | Installed, seed 9502 (us) | Selected variant, seed 9502 (us) |
|---|---:|---:|---:|---:|
| Merged down, N336/K10240 | 42.772 | 40.774 (grid 40/U4) | 43.500 | 40.634 (grid 40/U4) |
| Final down, N320/K10240 | 49.326 | 37.282 (grid 30/U4) | 49.495 | 36.484 (grid 30/U4) |
| Up, N10240/K320 | 35.043 | 34.768 (grid 40/U4) | 33.831 | 31.597 (grid 20/U2) |

U2 changes loop unrolling while retaining the native arithmetic. The second
run also tests combined grid/unroll choices; grid 40/U2 regresses for the
merged down operator. A global replacement of 20 by 40 is inappropriate.
The full-model gain is unproven. Applying the observed reductions to the
profile's HC budget suggests roughly 0.5 ms per target graph, not enough
alone to establish 60 output tokens/s. Actual model weights and serving
before/candidate/after comparisons remain required.

The initial combined-test attempt selected a U2 mode using an older library
that did not implement that mode. After a rejected null-argument launch, an
incorrect retry dispatched the packed kernel with unsuitable descriptor
pointers and caused an isolated GPU memory fault. This was a test setup error,
not evidence against U2. The serving tool checks passed afterward. The
corrected test pins a newly built library and completed all cases. No serving
source was modified. Full stderr remains in the session execution history.

The first grid-only test pins library SHA256
`ae7c17353a341bca79219f4a22346ba9a96ee5a4202932d8bc6609cc675b0344`.
The combined test pins
`8ab4de1bd05abaf4f0188a1e82aa6a1f69e53acb8ed2cc63444e5f06b6b854bc`.
Its source is generated by the existing HC lossless source generator from
the pinned vLLM skinny GEMM source, including explicit native U1/U2 modes.
Tests are `tests/bench_hc_grid.py` and `tests/bench_hc_grid_u2.py`; raw timings
are `bench/records/2026-09-09-hc-grid*.json`. Neither test is a production
adapter. Library mode compatibility must be checked against generated source.

## Gated vLLM adapter

`patches/hc_native_grid.py` provides a default-off adapter gated by
`STRIX_HC_NATIVE_GRID=1` and a hash-checked `STRIX_HC_NATIVE_LIBRARY`.
It registers a custom op and selects only named target HC projections,
contiguous BF16 tensors, no bias, four input rows and the three tested matrix
shapes. Other inputs retain the original `UnquantizedLinearMethod.apply`.
MTP and visual prefixes are excluded. The installed service is unchanged.

The adapter test (seed 9503) exercised the patched linear method and custom op
on 72 synthetic matrices. All eager and changed-input graph results matched
the installed operator bitwise. Median times in microseconds were:

| Shape | Installed | Adapter |
|---|---:|---:|
| M4/N336/K10240 | 43.199 | 40.637 |
| M4/N320/K10240 | 49.370 | 39.061 |
| M4/N10240/K320 | 34.199 | 31.780 |

See `tests/bench_hc_adapter.py` and
`bench/records/2026-09-09-hc-adapter.json`. These checks cover the actual
adapter in isolated eager and HIP graph execution; full-model compilation,
actual checkpoint tensors and serving performance remain unverified.
