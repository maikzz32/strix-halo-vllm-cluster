# Explicit W1 loop pipelining

The current expert-ordered W1 kernel already loads a weight tile shared by its
BM16 token tile. It retains four interleaved Split-K accumulations, each with
five K128 iterations. This experiment changes the loop to `tl.range` with
three or four stages and matches the launch `num_stages` accordingly. It keeps
the expert workgroup order, dot sequence, dequantization and final reduction.

The benchmark imports hash-checked current source on Node 4, extracts the W1
kernel to temporary modules and substitutes it only in the isolated process.
Dispatch counters verify selection. Each routing pattern rotates across 24
banks, with a packed working set of 114–226 MB. Five timing rounds alternate
method order and replay each 24-bank graph 20 times.

| Routing pattern | Current, us | Three stages, us | Four stages, us |
| --- | ---: | ---: | ---: |
| Shared ten experts | 35.963 | 36.341 | 45.080 |
| Partially overlapping experts | 70.686 | 72.540 | 83.190 |
| Forty distinct experts per bank | 107.412 | 108.927 | 124.997 |

Both candidates pass every bank's exact output comparison and graph replay
with changed inputs. Serving counters remain unchanged. Neither candidate
improves the current kernel, so neither is deployed. No register or occupancy
cause is established by this timing-only experiment.

The first controller attempt failed on a Python import scoping error before
kernel execution; the corrected complete run is `w1-pipeline-20260910-r2`.
Evidence: `tests/bench_moe_w1_pipeline.py` and
`bench/records/2026-09-10-w1-pipeline.json`. These are synthetic operator timings,
not a new ShareGPT result. Production weights and source remain unchanged.
