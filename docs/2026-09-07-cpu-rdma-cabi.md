# CPU transport C ABI preparation, 2026-09-07

`tools/cpu_rdma_transport.c/.h` extracts the tested four-rank RC allgather/AVX2 sum into a small opaque C context. The standalone benchmark and its measured source remain unchanged. This is preparation for a coupled HIP graph microbenchmark, not a vLLM backend or serving modification.

The public API is `cpu_rdma_create`, `cpu_rdma_run`, `cpu_rdma_destroy`, `cpu_rdma_last_error` and the CPU-only `cpu_rdma_numerics_selftest`. The wrapper and C backend share the exact header. Parameters explicitly fix ABI1, four ranks, 10,240 BF16 values, HCA/GID/port, numeric bootstrap IPv4, a 32-hex run ID and a 100–120000 ms per-operation timeout.

The caller lends one 64-byte-aligned, exactly 204800-byte host arena. Slots0–7 retain the tested two sets of four receive slots, slot8 is stable input and slot9 stable output. Create registers the entire arena once through verbs. Run accepts only those exact input/output pointers, checks mode/count, completes all sends/receives, reduces in fixed rank order and returns after input reuse is safe. It performs no allocation, registration, TCP barrier, HIP API call or output logging. Pointer stability across graph replay is explicit. The two alternating receive slots and per-peer monotonic sequence checks are unchanged.

There are no global signal handlers, alarms or process exits. Context deadlines bound software polling/bootstrap and are checked again before success. An operation error poisons the context. Destroy releases QPs before MR/CQ/PD/device and never frees the borrowed arena. A teardown failure retains the context and requires the arena to remain alive until successful cleanup or process exit. Native driver calls themselves are not cancellable by the software deadline; the owning isolated test still needs an external hard process timeout.

Both modes retain the validated numerical primitive: FP32 accumulation/final BF16, or BF16 rounding after every addition. The C self-test uses stack blocks, no heap/device/network access, and covers all 32 banks plus eight sets of all65,536 raw BF16 patterns. It checks RNE with disabled FTZ/DAZ without changing control settings. Create/run fail closed on incompatible thread FP control state. NaN exercise can set ordinary exception status flags; those flags must be distinguished from masks, rounding and FTZ/DAZ when the wrapper compares main/callback environments.

The module was compiled as C11 using the existing **Node15 ray-head Fedora44 container** toolchain: C object, shared library, unit executable and a C++ consumer of the C object all built and exited0. No Fedora45 host binary/library was moved into that container. `tests/test_cpu_rdma_transport.c` links with `--wrap=ibv_get_device_list`, so the guard test's one device query is mocked and opens no NIC. It passed numerical parity, FP-state rejection, invalid arguments and preservation of caller input/output storage after create failure. Validation evidence is in `bench/records/2026-09-07-cpu-rdma-cabi-cpu.json` in the repository (also `research/cpu-rdma-cabi-container-validation-20260907.json` in the workspace).

For the coupled test, compile the C module in each actual runtime container with GCC `-O3 -std=c11 -fPIC` and link its object with the HIP C++ wrapper using the header's `extern "C"` declarations plus libibverbs/libm. The HIP wrapper owns the pinned allocation, GPU→host readiness and host→GPU visibility, self-tests the actual callback thread, measures the complete graph and validates repeated nonzero outputs. No new RDMA traffic or GPU test was run during this preparation scope.

Independent read-only review found no concrete defect in the borrowed-arena failure paths, teardown order, per-context deadline or double-buffer/ahead-one logic.
