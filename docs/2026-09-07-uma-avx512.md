# Exact AVX-512 reduction in the UMA backend

An isolated AVX-512 implementation lowers the coupled GPU/UMA collective time from approximately 54.1 us to 48.0 us, with fresh bit-exact parity against active PyNccl on all four nodes. The serving library has not been switched. A separate candidate library/config is staged for a full-model comparison.

## Arithmetic and CPU checks

The candidate expands sixteen BF16 operands per vector instead of eight. It retains sequential FP32 additions and the original per-add BF16 round-to-nearest-even conversion using integer bit operations. It also avoids repeating the final conversion after an already rounded BF16 result. It does not use a BF16 conversion instruction that could silently flush subnormals. Blocks containing nonfinite inputs use the existing scalar reference to preserve NaN sign/operand behavior. A capability check falls back to AVX2 when AVX-512F/BW is unavailable.

All four nodes report the required features. Each passes 3614 checks: full 16-bit input patterns, cancellation, exceptional values, both rounding modes of the primitive, lengths 0–65, unaligned offsets, output canaries, unchanged FP control state and 32 complete Ring4 input banks. These are exhaustive single-input encodings in the tested patterns, not all possible four-input combinations.

| Node | AVX2 rotating 32-bank median (us) | AVX-512 median (us) |
|---|---:|---:|
| 15 | 9.141 | 3.557 |
| 16 | 8.961 | 3.534 |
| 17 | 8.900 | 3.510 |
| 18 | 8.786 | 3.455 |

The CPU-only benchmark uses malloc buffers and creates no verbs or HIP context. A separate real-RDMA comparison alternates AVX2/AVX-512 in 32-call blocks and checks every output against the original host reference. All 960 collectives per rank pass. Median whole-collective time changes from 44.99–45.10 us to 39.57–39.62 us; median wait remains approximately 35.2–35.4 us while reduction drops from 8.83–9.04 us to 3.58–3.69 us.

## Coupled GPU/UMA control bracket

Same one-kernel UMA transport, 1024 GPU threads, 20 KiB BF16 payload, 32 graph operations, 32 replays and three samples. Every run creates its own contexts and validates 32 fresh input banks against the active PyNccl implementation in eager and graph execution before timing.

| Backend | Maximum rank median HIP time (us) |
|---|---:|
| AVX2 before | 54.09878 |
| AVX-512 candidate | 47.97575 |
| AVX2 after | 54.08085 |

The candidate reduces collective time by 11.29% versus the stronger control. All ranks pass numerical/graph checks and cleanup; serving remains idle with unchanged completion counters. The model process and its loaded library remain unchanged throughout.

At the previously observed 97 target collectives, a 6.1 us reduction corresponds to roughly 0.6 ms per target round if the isolated difference survives in context. This is an estimate, not a measured model-throughput improvement or completion of the single-answer goal.

## Staged model candidate

All four nodes contain the same new library at `/opt/strix-halo-next/hip-uma-avx512-20260907-r1/libhip_rdma_backend.so`, SHA256 `69a8d604b028244d219a645471bea34eb28b53510c660b231cfd323b859dbfba`. Its source generator is hash-guarded and the native ABI is unchanged. The existing Python wrapper and runtime communicator hook can use it without alteration.

The separate [candidate configuration](../bench/records/hip-uma-wide-model-r1.json) changes only `STRIX_HIP_RDMA_LIBRARY`; the wrapper path, weights, context, MTP3 and original W1 remain unchanged. It is copied to all hosts as `config/hip-uma-wide-model-r1.json`. Canonical `cluster.json` still selects the original library. The next model test must compare identical requests and outputs, then restore canonical configuration before deciding whether to promote.

[Full evidence and source hashes](../bench/records/2026-09-07-uma-avx512.json) includes both CPU tests, all three coupled runs and staged binary identities. Source versions are archived in local result directories.

The CPU drivers `run_cpu_rdma_wide.py` and `run_cpu_rdma_widenet.py` default to dry run. The coupled driver adds `--avx512-reduce` to the existing `--backend-test --uma-backend --uma-threads 1024 --mode ring4` options. `stage_hip_uma_wide.py` only builds a separate library and refuses to overwrite its fixed staging directory; it does not activate anything. All drivers require explicit `--execute` for work on the hosts.
