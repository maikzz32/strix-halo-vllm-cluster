# HC-up projection and gate-mix fusion

The fixed-M4 candidate is staged on all four nodes, but **not integrated into
serving**. No model-level gain has been established.

Original dot-product reduction, BF16 gate rounding, four-stream FP32 FMA order
and final BF16 conversion are retained. A 65,536-entry FP32 lookup table (256
KiB) is generated using the installed Triton sigmoid. A separate finite-BF16
probe found 668 FP32 differences with HIP expf/division; that prototype failed
expanded output parity and was rejected. Eight lanes distribute the epilogue.

## Isolated results

Microseconds per combined operator; six alternating rounds, 12 rotating weight
banks and 20 graph replays per round. Grid 60 is launch geometry, not CU count.

| Node | Installed | Fused grid 60 | Latency reduction |
|---|---:|---:|---:|
| 1 | 35.425 | 31.172 | 12.01% |
| 2 | 35.917 | 31.222 | 13.07% |
| 3 | 36.341 | 31.195 | 14.16% |
| 4 | 35.535 | 31.073 | 12.56% |

Seed 9569 passed on all four nodes: exact intermediate BF16 gates and final
outputs for grids 20/30/40/60; additional scales 0/4/32 on four banks; exact
changed-input graph replay without diagnostic gate stores. Serving counters
were unchanged. Earlier seeds 9567/9568 passed on Node 4. Synthetic tests do
not establish parity for actual checkpoint activations.

## Remaining requirements

The native ABI assumes BF16 weights [10240,320], input [4,320], residual
[4,10240] and output [4,2560]. It does not check a null table pointer. The
serving adapter must enforce valid shapes/pointers, initialize and retain the
table outside graph capture, register a custom operation/fake implementation,
and preserve unsupported-shape and MTP fallbacks.

Actual dispatch/capture validation, ShareGPT48/C1, Hermes and output parity
with matched controls remain outstanding. Prior HC geometry and W1/SiLU fusion
microbenchmarks did not deliver serving gains; this candidate is not promoted.
