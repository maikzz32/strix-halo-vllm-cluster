# HC-up projection and gate-mix fusion

The fixed-M4 native candidate passed isolated checks. Its first serving
integration did not reach the compiled decode graph; the dynamic-dispatch
correction reached the full graph but failed full-model output parity. It is
not promoted. No model-level gain has been established.

Original dot-product reduction, BF16 gate rounding, four-stream FP32 FMA order
and final BF16 conversion are retained. A 65,536-entry FP32 lookup table (256
KiB) is generated using the installed Triton sigmoid. A separate finite-BF16
probe found 668 FP32 differences with HIP expf/division; that prototype failed
expanded output parity and was rejected. Eight lanes distribute the epilogue.

## Remaining requirements

The native ABI assumes BF16 weights [10240,320], input [4,320], residual
[4,10240] and output [4,2560]. It does not check a null table pointer. The
serving adapter must enforce valid shapes/pointers, initialize and retain the
table outside graph capture, register a custom operation/fake implementation,
and preserve unsupported-shape and MTP fallbacks.

Actual dispatch/capture validation, ShareGPT48/C1, Hermes and output parity
with matched controls remain outstanding. Prior HC geometry and W1/SiLU fusion
microbenchmarks did not deliver serving gains; this candidate is not promoted.


## Initial integration test

The default-off, hash-guarded source transformer replaces the adjacent pair in
both actual `GatedResidual.mix` and `combine_and_mix`. The runtime initializes
a shared per-device sigmoid table before capture, holds it as a non-persistent
buffer, and registers a custom operation with descriptor checks and a fake
implementation. Target prefixes and unquantized BF16 weights are required.
MTP prefixes and unsupported row counts retain the original path.

Node 4's bounded isolated integration test passed 32 exact-output cases: both
actual HC methods, combined/separate down projections, target/MTP prefixes,
and row counts 1/3/4/5. The test uses synthetic projection modules and explicitly
calls preparation; **it does not exercise the real vLLM layer constructor or
checkpoint loader**. The pair compiles with `torch.compile(fullgraph=True)`
using a graph-inspecting eager backend, which confirms the new custom operator
is present. Changed-input HIP graph replay also matches exactly. This is not
an Inductor or full-model compilation result. Serving counters were unchanged.

See `patches/hc_up_mix_{source,runtime}.py`,
`tests/check_hc_up_mix_integration.py` and the corresponding controller/record.
Real constructor/device initialization, model capture and matched serving
validation remain required before promotion. Production sources are unchanged.

## First serving trial: dispatch failure, not a fusion performance result

TP4/MTP3 run `191da44d7f45484d9cdc15fbf2722526` completed ShareGPT48/C1 at
56.1896 tokens/s, mean TTFT 549.933 ms and mean TPOT 15.563 ms. The preceding
control was 56.2861 tokens/s. All 48 texts, output lengths and speculation
statistics matched; Hermes checks passed.

Although the source and mapped library were verified on all ranks, the captured
target graph still had 2646 nodes (2558 kernels, 88 copies). The freshly compiled
rank-0 computation_graph.py contained no `strix_hc_up_mix` operation and retained
the original gate-mix operations. Thus this run does not test fused serving
performance. It must not be used to reject or promote the native fusion.

The outer Python M4 guard was unsuitable for the broad dynamic compilation
range. The correction in `hc_up_mix_dynamic.py` puts shape/layout dispatch inside
the custom operation and gives its fake implementation a dynamic leading size.
The outer condition now uses only static layer eligibility. Unsupported sizes
invoke the original GEMM and gate-mix operators.

The new test compiles at M2 with a dynamic size range, then executes M4/M3/M5/M4
through the same single Inductor graph. A test-only wrapper counts actual native
calls: one per M4 invocation, zero for the fallback sizes. Outputs must match
exactly. This closes the fixed-shape test gap; full-model dispatch still needs
verification after the corrected integration is deployed.

The dynamic-dispatch test now passes on all four nodes, including real HC
constructors, full-method Inductor checks and changed-input graph replay.
Serving counters remained unchanged during these isolated checks. The correction
has subsequently entered the full-model trial described below.

## Corrected serving trial rejected

The full trial completed at **56.3334 tokens/s**, mean TTFT 555.604 ms and
mean TPOT 15.480 ms. This is only +0.084% throughput against the preceding
56.2861 control and is not evidence of a useful speedup. More importantly,
only **14/48 generated texts match**; output lengths and speculation statistics
also differ. It generated 11810 tokens instead of 11839. Acceptance decreased
from the control trajectory; the candidate reports 52.60% and 2.58 acceptance
length. Hermes checks pass, but that does not establish arithmetic parity.

The fusion is rejected for production. The original per-node HC sources were
restored and a fresh MTP3 control is starting. Its measurements are pending.
The synthetic tests did not cover the full-model source of divergence. A future
investigation must compare actual checkpoint activations and intermediate gates
before considering another performance trial; the cause is not yet identified.

## Actual-activation audit: no pairwise numerical mismatch

The diagnostic completed all 48 requests and Hermes checks. Each rank recorded
4615 M4 comparisons for each of 97 HC layers: **447655 comparisons per rank,
1790620 across TP4**. Gate and output BF16 bit differences were both zero.
No first-error snapshots were created. Collection took place with unchanged
serving counters. This tests both implementations on the same actual inputs
inside the diagnostic execution, not on the original run's activation sequence.

Despite returning the reference pair's output, all 48 diagnostic responses,

performance result. The diagnostic was stopped; original HC files were restored

## Restoration and graph-context follow-up

The original-path control completed at **56.1955 tokens/s**, **557.923 ms
mean TTFT**, and **15.3994 ms mean TPOT**. All 48 texts, output lengths,
and speculation statistics match the earlier original control; Hermes auto
selection, result roundtrip, streaming, and default-thinking checks pass.
The restored TP4 service retains the original checkpoint and HC source.

A read-only comparison of rank 0's saved graph modules found the expected
97 original GEMM/gate pairs replaced by 97 audit calls. Expanding those audit
calls into their reference expressions and resolving local assignments yielded
matching return expressions for all 99 backbone segments and all 3 MTP
segments. This is a symbolic diagnostic, not a proof of runtime equivalence:
it excludes outer graph wiring, storage lifetimes, actual layouts and kernel
selection. Cache-key factors differ only in the source code hash. No matching
emitted Inductor Python artifact for the audit operator was found in the
configured cache directory; its absence does not establish which backend ran.

An original-only custom-op control is being validated separately. It calls
both registered original operators and adds no LUT or tensor buffers. This
isolates the custom-op boundary from the native fused kernel and the audit's
extra allocations. It has not been deployed to the model service.

The isolated original-only control passed on node 4: 32 real-constructor HC
method cases, full-method Inductor checks, changed-input HIP graph replay,
and one dynamically compiled graph exercised at M=2/4/3/5/16/128/512/4.
All outputs match the original operators and serving counters remain unchanged.
These checks validate the diagnostic harness, not full-model response parity.


The outer graph wiring was also compared. After excluding audit-buffer
arguments, aliases, call arguments and release targets, and stripping type
annotations, the backbone outer AST is identical. The MTP outer AST is

## Original-only wrapper reproduces the response change

The TP4 control wrapping only the two registered original operators completed
at **55.9259 tokens/s**, **549.972 ms mean TTFT**, and **15.6609 ms mean TPOT**.
All 48 requests and Hermes tests passed. The captured target retained the
original 2558 kernels and 88 copies, and the current graph contained the

Only 14 responses match the unwrapped baseline. All **48 responses, output
lengths and speculation statistics match the native fused trial** instead:
11810 output tokens, 4583 drafts, 13749 draft tokens and 7232 accepted tokens.
The native kernel, sigmoid LUT, and audit buffers are therefore not necessary
to reproduce this change. The custom-op integration and its execution context
remain under investigation; this does not yet identify the first numerical
mismatch or prove a compiler defect. The wrapper is not promoted.

Lowered Python code was located in vLLM's separate `torch_aot_compile` cache.
The shared cache contains original, audit and fusion variants. All five distinct
reduction kernel bodies match after normalizing function names. Most reduction
metadata also matches; one norm/sigmoid variant omits `tiling_scores` and has a
different kernel name. Actual autotuned launch choices still require comparison.
Several non-reduction kernels differ in combination/scheduling, including
embedding and zero initialization. These are leads, not established causes.

The original-only diagnostic was stopped while idle, original HC sources were
restored on every node, and a fresh original-path control is starting.


## Launch geometry produces a measurable numerical difference

The subsequent original-path control completed at **56.4758 tokens/s**, with
**553.933 ms mean TTFT** and **15.3775 ms mean TPOT**. All 48 texts, lengths,
and speculation statistics match the original reference; Hermes checks pass.

The saved autotuning records select XBLOCK=4 for the original norm/gate kernel.
An additional variant in the fusion, audit, and original-only-wrapper caches
selects XBLOCK=1. Both use two warps and one stage with the same reduction body.
An isolated test on node 4 launches that body with each geometry, holding all
inputs fixed. Across eight seeds and row counts 4, 128 and 1024, **26 BF16 output
elements differ**, with maximum absolute difference 0.00390625. One difference
also occurs at four rows. Serving counters remain unchanged throughout.

This establishes that the observed geometry change can alter numerical output.
It does not yet prove that these differences caused the 34 changed model
responses: that requires an actual-model trial preserving the original geometry.
The test and controller accept a hash-verified emitted kernel source and do not
change the running model. Current serving remains on the original path.


## Targeted geometry pin validated on all four nodes

The opt-in helper identifies the generated norm/gate body by normalized AST
SHA256 and requires gfx1151. It overrides that autotuner's configuration in
memory to XBLOCK=4, two warps and one stage, including when cache lookup supplies
XBLOCK=1. It disables cache writes for that autotuner. Other kernel bodies are
not selected. Python 3.12's empty `type_params` field is normalized for hash
compatibility with the controller's Python 3.10.

All four nodes pass the isolated test: pinned execution matches the original
geometry in all 24 input cases, changed-input HIP graph replay is exact, and
selection plus precompilation records show the requested geometry. Serving
counters remain unchanged. This validates the helper and graph replay; the
helper has not yet been deployed to TP4 model serving, so model response parity
and performance remain unproven.
