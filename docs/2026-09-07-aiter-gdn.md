# AITER packed GDN recurrence on gfx1151

The adapted AITER post-convolution recurrence is faster in an isolated MTP operator test. Full-model integration and its effect on ShareGPT C1 remain unproven. Serving was not changed.

Pinned AITER: `e8eac17259db6efcb48eba2aa0d9a3bf422e7b35`. Tests use the existing Node18 container and an isolated Python-only AITER checkout. See [machine-readable trials](../bench/records/2026-09-07-aiter-gdn.json).

## Correctness and comparison corrections

The unmodified upstream kernel failed whole-state equality because vLLM reserves state index zero, while AITER treats zero as valid. The adapted kernel changes only the initial-state guard to `<= 0` and the final-state guard to `> 0`; arithmetic is unchanged.

Trial r2 used separate contiguous copies as the reference and overstated the benefit. Trial r3 compares against a compiled concatenation matching vLLM's `rearrange_mixed_qkv`, but included a null write slot in timing. Trial r4 corrects both issues and is the contiguous-layout timing reference.

Trial r4 checks local H=4, HV=12, K=128, V=128, four tokens per request, batches 1 and 2, FP32 and BF16 state, eight input banks and accepted counts 1 through 4. All 128 whole-state checks pass bitwise; all 112 defined output comparisons pass bitwise. Sixteen output comparisons are excluded because the reference returns without defining output when the selected initial state is null. Changed-input and changed-acceptance graph replay checks also pass. Timing uses valid state slots, five alternating-order samples of 100 graph replays.

| Batch | State | Compiled reference (us) | Adapted AITER (us) | Latency reduction |
|---|---|---:|---:|---:|
| 1 | FP32 | 13.1232 | 10.7025 | 18.45% |
| 1 | BF16 | 10.2385 | 8.4026 | 17.93% |
| 2 | FP32 | 17.6223 | 14.5544 | 17.41% |
| 2 | BF16 | 13.0840 | 10.8429 | 17.13% |

These are microseconds per operator, not milliseconds per model step. Convolution and subsequent normalization are excluded. No claim of model throughput follows from these timings.

## Integration boundary

The installed `qwen_gdn_linear_attn.py` speculative branch calls `rearrange_mixed_qkv(mixed_qkv_spec)` before `fused_sigmoid_gating_delta_rule_update`. An optional packed-QKV implementation can eliminate that rearrangement for the speculative branch while preserving the stock path for prefill and other layouts. Merely enabling the existing AITER flag does not select this MTP path.

Before deployment, validate the actual state and index strides, graph padding, mixed accepted counts, and concurrent requests. Preserve the original implementation as an explicit fallback; compare full-model outputs, accepted-token behavior and ShareGPT48/C1 throughput in a bracketed trial.

## Extended layout and graph checks

Trials r5 and r6 extend batches to 1, 2, 4 and 8, use transposed packed QKV, index rows with stride 8, and state slots with doubled outer stride. Entire backing state storage is compared, including unused gaps. Each trial passes 256 state checks and 224 defined output comparisons plus graph replay checks. Trial r6 additionally replays each graph with mixed per-request accepted counts and, for batches greater than one, a fully null final request; only defined output tokens are compared and the complete state storage must remain equal.

The B1/FP32 reference/candidate medians are 13.1284/10.6861 us in r5 and 13.0324/10.5909 us in r6, confirming about 2.4 us saved. B8 timings are less stable: BF16 is slower in r5 and faster in r6. Do not assume a robust B8 speedup or extrapolate these timings to serving throughput. All owned test processes exited, and the model's completed request counter remained 54 throughout both trials.

A future serving adapter should initially restrict the candidate to the verified small-batch speculative path, retain a stock fallback, and validate model outputs before promotion. These checks are not a substitute for that model test.
